# Source of Truth and Provenance

- Name the authoritative file or system for every major type of state.
- Inspect it before work and update it with the decision it represents.
- Search across the relevant repository before adding or revising information to find duplicates, alternate wording, references, contradictions, and material that may become outdated.
- Actual current files outrank memory, summaries, and old conversation state.
- When asked to add, append or integrate; do not replace existing material silently.
- Keep one clearly identified current statement for each governed fact or rule. Consolidate duplicates and update links, summaries, templates, and adapters that repeat it.
- Mark superseded information with the replacement, decision, date, and reason when retaining it outside version history is useful.
- Preserve exact questions, alternatives, objections, rejected directions, dependencies, disagreements, and rationale while review is active.
- Keep reviewer provenance using project markers. Default markers are `[HUMAN: Name]` and `[AGENT: Name]`; established markers such as `[GPT]`, `[CLAUDE]`, and `[PERPLEXITY]` remain valid.
- The user is final decision owner unless authority is explicitly delegated.
- A design decision is not implementation evidence; a prototype is not production proof.
- A final consolidation requires explicit approval and a traceable mapping from reviewed material to the clean specification.
- Never let an issue, chat, plan, or AI memory become the only record of a material change.
