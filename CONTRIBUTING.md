# Contributing

## Skill structure

Every skill requires `skills/<skill-name>/SKILL.md` with YAML frontmatter containing `name` and `description`. Add `references/`, `scripts/`, or `assets/` only when they provide concrete reusable value.

## Submission checklist

- The skill solves a distinct, repeatable task and its description routes requests precisely.
- It does not duplicate an existing skill or preserve guidance superseded by newer information.
- Instructions are concise, feasible, vendor-neutral where practical, and preserve user intent.
- Claims, compatibility statements, and external links were checked.
- No secrets, private data, proprietary content, or prompt-injection instructions are included.
- Third-party ideas or adaptations include source, license, and attribution where required.
- New or changed scripts were run safely; `SKILL.md` frontmatter and internal links were validated.
- Material behavior changes include a regression case or evaluation note.

Use pull requests for contributions. Explain the use case, boundaries, evidence or provenance, validation performed, and any known limitations.
